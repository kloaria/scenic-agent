# 陈家祠知识库结构划分说明

> **文档目的**：说明知识库的数据结构划分、文件组织方式、数据流向和使用方法

---

## 一、整体架构

陈家祠知识库采用**双向输出**架构，每条原始数据同时处理为两份输出：

```
原始数据（11个文件）
    ├── 向量数据库_待入库语料/（长文本叙述，用于语义检索）
    │   ├── 01_整体概况.md
    │   ├── 02_建筑艺术.md
    │   ├── 03_展厅与展品_长文本.md
    │   ├── 04_游览路线.md
    │   ├── 05_参观公告.md
    │   ├── 06_馆藏藏品_长文本.md
    │   ├── 07_内部方位地图.md
    │   ├── 08_解说词.md
    │   ├── 10_保护与维修.md
    │   └── image_mapping.json
    │
    └── 知识图谱_待入库数据/（结构化实体+关系，用于图谱推理）
        ├── entities.json
        ├── relationships.json
        └── entity_schema.json
```

## 二、数据划分原则

### 2.1 向量数据库语料

**用途**：用于embedding后进行语义检索，支持自然语言问答

**特点**：
- 保留完整的长文本叙述
- 每个实体/条目都有完整的描述
- 图片信息以"【关联图片：xxx】"形式嵌入文本
- 数据来源标注在每个条目末尾

**文件说明**：

| 文件名 | 内容 | 数据量 |
|:---|:---|:---|
| 01_整体概况.md | 陈家祠历史沿革、建筑地位、核心价值 | 完整叙述 |
| 02_建筑艺术.md | 282件建筑装饰作品的完整描述 | 282件全量 |
| 03_展厅与展品_长文本.md | 8个展厅及63件展品的完整介绍 | 全量展品 |
| 04_游览路线.md | 7条推荐游览路线及空间导航 | 全量路线 |
| 05_参观公告.md | 开放时间、票务、服务设施等 | 全量信息 |
| 06_馆藏藏品_长文本.md | 693件馆藏藏品的完整信息 | 693件全量 |
| 07_内部方位地图.md | 空间节点、连接关系、公共设施 | 全量空间数据 |
| 08_解说词.md | 完整解说词文本 | 全量解说 |
| 10_保护与维修.md | 保护历程、修缮工程、排水改造 | 全量记录 |
| image_mapping.json | 图片与实体ID的映射关系 | 693条映射 |

### 2.2 知识图谱数据

**用途**：导入图数据库（如Neo4j），支持实体关联查询和图谱推理

**特点**：
- 实体结构化为JSON格式
- 每个实体包含images字段（图片URL数组）
- 每个实体包含source字段（规范的数据来源标注）
- 关系三元组包含source字段

**文件说明**：

| 文件名 | 内容 | 数据量 |
|:---|:---|:---|
| entities.json | 全部实体（含images和source字段） | 1084个实体 |
| relationships.json | 全部关系三元组（含source字段） | 2739条关系 |
| entity_schema.json | 实体类型Schema定义 | 14种实体类型、16种关系类型 |

## 六、使用方法

### 6.1 向量数据库构建

1. 读取 `向量数据库_待入库语料/` 目录下的所有 .md 文件
2. 按章节切分（以 `##` 或 `###` 为分隔）
3. 对每个文本块进行embedding
4. 存储embedding和原文，建立索引
5. 导入 `image_mapping.json` 用于图文关联检索

### 6.2 知识图谱构建

1. 读取 `entities.json`，创建节点（每个实体为一个节点）
2. 读取 `relationships.json`，创建边（每个关系为一条边）
3. 参考 `entity_schema.json` 验证数据结构
4. 导入图数据库（如Neo4j）

### 6.3 联合检索

- 用户提问 → 向量库语义检索 → 返回相关文本和图片
- 实体查询 → 图谱关联查询 → 返回关联实体和关系
- 路线推荐 → 图谱路径推理 + 向量库内容补充
